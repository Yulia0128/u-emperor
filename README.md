# U皇万岁 · v0.3.0 黑曜大理石版

SillyTavern 原生角色卡管理扩展。整体采用黑曜石大理石风格：黑底、暖浅字、衬线字体、宽字距与留白。卡框为 1px 金银细线和柔和光晕，皇后最亮，其他妃位逐级收敛；按钮均为纯平实色，无渐变、内阴影或浮雕。翻牌使用深胡桃木、玉色牌头和细金边。采用固定黑金配色，避免外部主题改变文字对比度。目标最低版本为 **SillyTavern 1.15.0**，不依赖酒馆助手、不请求模型。

## 安装与更新

1. 解压 `u-emperor-0.3.0.zip`，得到 `u-emperor` 文件夹。已有 0.1.0／0.2.0 时用新文件覆盖原扩展目录，封位与原帖等数据保存在酒馆设置中，不需重建。
2. 将整个文件夹放到酒馆安装目录的 `public/scripts/extensions/third-party/` 下，确认实际路径为 `public/scripts/extensions/third-party/u-emperor/manifest.json`，不要多嵌套一层。
3. 刷新酒馆，右上角原生角色抽屉默认显示管理器；也可以进入「扩展 → U皇万岁 → 打开管理器」或聊天区扩展菜单。原生首页展示与角色面板替代可分别关闭。

右上角角色面板中点击「原生面板」可临时回到原生界面；编辑和创建也会切到原生表单。点击「返回 U皇万岁」或再次点击原生角色入口回到管理器。停用扩展会恢复原生节点和可见性，不删除原生界面。

本版未发布到远程 Git 仓库，因此暂不能通过 GitHub 链接安装或在线拉取更新。后续提供仓库后可沿用原生扩展更新流程。不要同时加载重复副本。

优先打开带版本号的 `dist/U皇万岁-v0.3.0-离线预览.html`，便于确认所看版本。`dist/U皇万岁-离线预览.html` 也同步更新。里面使用示例角色和本地矢量占位封面，不读写真实酒馆；安装后显示用户自己的角色封面。预览数据只保存在浏览器。

## 已实现

- 皇后最多一位；其余默认皇贵妃、贵妃、妃、嫔、贵人、未册封、冷宫。妃位可改名、调整权重、增加、删除与上移排序；皇后、未册封和冷宫的特殊规则固定。
- 皇后最大展示；全部妃位放入按需打开的分类抽屉，手机不保留常驻左栏。角色名与标签搜索、原生标签筛选；筛选时只显示有匹配角色的妃位，不显示局部空皇后等占位。大量角色分批渲染、封面懒加载。
- 翻牌仅由按钮打开。初始界面只显示仿真托盘和五枚牌，规则、盲翻／点名、标签和妃位都收进「翻牌设置」。桌面与手机均展示五牌；点名不足五位时，其余为不可点击的空牌，不用重复角色填满。
- 托盘使用可验证加载的独立 PNG 图片，不依赖 CSS 背景；托盘前沿、牌子和盘底分层，结合接触阴影与轻微倾角表达牌子放在盘内的效果。手机保留托盘素材原始比例，五枚牌保持可点击。
- 点击或轻触以约 600ms 沿 Y 轴翻牌，揭晓后轻抬并露出侧边；其他按钮提供约 500ms 的低强度光晕与居中展开的金色下划线，卡框光影以 700ms 缓变。普通控件不位移、不缩放、不做按压浮雕；无音效、无本轮去重，尊重系统减少动态效果设置。
- 完全随机、情有独钟、喜新厌旧、旧情复燃四种规则，始终排除冷宫。
- 档案、开场、关联／内嵌世界书、同角色多存档集中查看。资料和聊天以纯文本预览，避免预览执行卡内脚本。
- 继续上次、使用某一开场建立新故事、存档显示名、置顶、原生消息数与最后时间、聊天预览和原生删除。首次打开存档列表时默认置顶上次存档（找不到则用最近一份），之后尊重用户的置顶／取消操作。
- 入宫登记：妃位和一个 Discord 原帖。未登记默认未册封。导入支持多个本地文件或原生下载接口支持的 URL。档案只有一个更新／替换入口，支持本地文件或下载网址，网址可跳转；不在档案展示翻到、查看等计数。
- 管理备份 JSON 导出与恢复；恢复前下载旧配置。角色库快照 ZIP 包含角色 PNG、聊天 JSONL、已关联世界书和管理备份。

## 翻牌规则与时间口径

- **完全随机**：每张非冷宫角色卡权重都是 1。
- **情有独钟**：单卡权重等于其妃位权重。默认从皇后的 8 到未册封的 0.5，不保证高位每次出现。
- **喜新厌旧**：单卡权重取妃位权重的倒数，与是否没玩过无关。
- **旧情复燃**：只考虑有实际聊天记录的角色。权重为 `log₂(1 + 历史用户消息数)² × (1 + ln(1 + 距上次游玩的天数))`，未玩天数上限 3650；历史投入为主。原生用户消息数作为历史投入，避免将每次重抽的 AI 回复再当作一次投入。妃位不参与这项计算。

没有候选时提示更换规则或筛选，不会悄悄换模式。没有统计数据时，旧情复燃显示错误和重试入口，不冒充完全随机。

入宫时间优先使用首次登记时保存的原生导入日期，替换同标识卡片时保留。历史日期不可用则显示未知。陪伴显示从首次实际聊天到今天的自然日数，不使用原生的模型生成耗时。

翻到、查看、进入存档、实际聊天分别记录。只打开旧档不会更新插件自己的最后游玩记录；实际聊天通过非群聊的原生消息事件记录。历史投入和历史日期来自酒馆统计，导入旧聊天或酒馆重建统计后可能存在近似值。

## 备份边界

管理 JSON 不含角色正文或聊天正文。角色库快照 ZIP 是当前角色库的逐项读取快照，不是整个账号的完整备份：不含群聊、外置图片／脚本资源、预设、API 配置和整个酒馆设置。超过 256 MB 停止并提示使用酒馆原生数据备份。生成失败时不提供假装完整的压缩包。

首版仅自动恢复管理 JSON。ZIP 中的角色、聊天、世界书由用户通过酒馆原生入口导入，`index.json` 记录其对应关系；不会自动覆盖恢复真实聊天。正在聊天的同时导出，文件间可能存在时间差，建议空闲时导出。

## 已知限制与验证

本版已通过规则／接口模拟测试、浏览器离线交互和 320／390 像素竖屏检查；当前工作区没有连接真实 SillyTavern，**未完成真实酒馆安装、聊天保存、开场切换、更新替换和世界书跳转验收**。请按 `docs/RUNTIME-CHECKLIST.md` 进行首轮试用。

原生标签编辑和角色创建由原生界面负责。第三方深度改造首页／角色抽屉的美化可能影响挂载，可关闭首页展示或「替代右上角原生角色面板」，从扩展菜单进入管理器。世界书预览不会执行 EJS、宏或脚本。角色面板替代已通过模拟宿主 DOM 检查，仍需在真实酒馆确认抽屉、固定／拖动、创建和编辑流程。

## 开发

源码在 `extension/`，设计原稿保留在 `design/`。无框架、无线上 CDN 依赖，压缩库 fflate 已随包附带及保留 MIT 许可证。

```powershell
npm test
npm run check
npm run test:ui
npm run package
npm run preview
```

静态检查／UI 检查／离线预览打包需要开发依赖 `css-tree`、`playwright-core`、`esbuild` 和可用 Chrome；工具可使用工作区现有安装，或执行 `npm install`。Chrome 路径可用 `CHROME_PATH` 指定。浏览器测试使用本地文件响应，不请求外网。
