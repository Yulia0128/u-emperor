# U皇万岁 · v0.7.10 后宫画廊

SillyTavern 原生角色卡管理扩展。整体采用黑曜石大理石风格：黑底、暖浅字、衬线字体、宽字距与留白。首页为后宫横向画廊，所有卡片同尺寸 3:4；前三位分别使用金、银、铜细边和光晕，后续逐级减弱。按钮均为纯平实色，无渐变、内阴影或浮雕。翻牌使用深胡桃木、玉色牌头和细金边。采用固定黑金配色，避免外部主题改变文字对比度。目标最低版本为 **SillyTavern 1.15.0**，不依赖酒馆助手、不请求模型。

## 安装与更新

推荐通过酒馆「扩展 → 安装扩展」输入仓库地址安装：

`https://github.com/Yulia0128/u-emperor`

已通过仓库安装的用户可在酒馆扩展管理中检查更新，更新后强制刷新页面。不要同时安装多个副本。以下为已有 ZIP 安装包的手动安装方式。

1. 解压 `u-emperor-0.7.10.zip`，得到 `u-emperor` 文件夹。已有旧版本时用新文件覆盖原扩展目录，封位与原帖等数据保存在酒馆设置中，不需重建。升级后强制刷新酒馆，电脑可按 Ctrl+F5。
2. 将整个文件夹放到酒馆安装目录的 `public/scripts/extensions/third-party/` 下，确认实际路径为 `public/scripts/extensions/third-party/u-emperor/manifest.json`，不要多嵌套一层。
3. 刷新酒馆，右上角原生角色抽屉默认显示管理器；也可以进入「扩展 → U皇万岁」，勾选「启动插件」后点击「打开管理器」。首页展示默认为关闭，已有保存的开关选择保留。聊天区小魔棒菜单不再增加入口。详细设置与备份统一从管理器右上角齿轮进入。

取消勾选「启动插件」立即恢复原生首页／角色面板，暂停游玩记录，管理数据保留；「打开管理器」随之禁用。重新勾选即可恢复，原生首页展示与角色面板替代仍按之前各自保存的偏好执行。

停用或卸载不删除角色卡、聊天存档、世界书、标签和其他扩展数据，也不会撤销用户已保存到原生角色卡的人设修改。SillyTavern 1.18.0 卸载时可勾选原生提供的「同时清理扩展数据」：仅删除 `extensionSettings.u_emperor`（封位、原帖、史册与本插件偏好），不勾选则保留以便重装恢复。旧酒馆不支持清理钩子时，卸载可能保留该设置项。停用不是清空数据。

右上角角色面板中点击「原生」可临时回到原生界面；新建角色仍进入原生表单。原生人设（description）可在插件档案的「编辑人设」中修改保存。点击「返回 U皇万岁」或再次点击原生角色入口回到管理器。停用扩展会恢复原生节点和可见性，不删除原生界面。

原生／史册／翻牌使用同尺寸和同描边，两排按钮共用右侧边线。移除手动刷新入口：初次加载与原生角色、聊天变更事件继续更新数据。封位导航以抽屉淡出、分类淡入切换，减少动态效果开启时直接切换。

分类切换、搜索和标签筛选使用已读取的统计；往返后宫与分类复用卡片及已载入封面，减少重复创建和解码。角色信息变化时仍会更新，封面首次加载使用异步解码和淡入。

公开仓库：[Yulia0128/u-emperor](https://github.com/Yulia0128/u-emperor)。仓库根目录包含 manifest.json，可直接使用酒馆原生扩展安装与更新流程。

优先打开带版本号的 `dist/U皇万岁-v0.7.10-离线预览.html`，便于确认所看版本。`dist/U皇万岁-离线预览.html` 也同步更新。里面使用 26 个示例角色和本地矢量占位封面，不读写真实酒馆；安装后显示用户自己的角色封面。预览数据只保存在浏览器，不模拟原生扩展设置页面。

0.3.1 修复了部分浏览器／HTTP 访问环境下 `crypto.randomUUID is not a function` 导致角色列表与弹窗无法使用的问题。用于界面和封位的标识现在独立生成，不依赖 Web Crypto，不修改其他扩展的全局环境，也不重建已有封位标识。

## 已实现

- 翻牌旁的「史册」提供内置日历、日历下方的周／月／年选择、往期与本期切换。点击金点日期，在该日期下方浮出「今日聊了 xxx 楼」，不另开弹窗；切换日期旧块淡出，全程复用一个悬浮块，无记录日期隐藏旧块。包含新增聊天总楼层、总Token、新入宫人数，以及「独占圣眷」「长相厮守」「青云直上」「藕断丝连」。各称号有数据时提供三句随数据变化的杂家语录，零值另有三句吐槽，同次打开保持稳定；不再显示记载口径与常驻统计说明。打开史册后顺序读取原生旧聊天，按实际日期补回楼层、已有Token和陪伴／重逢；首页不下载正文，同次运行再次打开复用结果，刷新管理器可重新读取。预览里的史册为独立示例数据，安装版不填入示例。
- 初封算晋升，记录当时封位顺序中的跨越级数（未册封至皇后默认 5 级，至贵人 1 级）和总耗时。青云直上按首次晋升的「耗时÷级数」评选；原生和已保存入宫日期均缺失时不猜晋升速度。藕断丝连采用连续 7×24 小时无互动门槛，久别最久者获得；同分并列获称号。
- 陪伴按进入角色聊天后有真实互动的自然日去重，和首次导入的入宫时间分开。只看档案不记陪伴；消息编辑、重抽、续写不重复增加楼层。「总Token」沿用已记录的用户与角色消息 Token 合计，不代表 API 总消耗，不额外分词或请求模型。部分楼层缺失时用 ≥ 标记已有合计，完全缺失显示破折号。暂停记录的区间、未知的历史与确实为零分开展示。

史册、封位和登记随酒馆账号设置保存到服务器。同一服务器、同一账号，换设备在原页面保存完成后重新加载可读取，无需手动导出导入。它不是多设备实时合并：两台设备／多个旧页面同时修改可能互相覆盖，未运行插件期间的册封等自定义事件无法补记，保留的原生聊天可在打开史册后补读。离线 HTML 演示仅存于浏览器，不使用账号服务器。
- 默认七个封位：皇后、贵妃、妃、嫔、贵人、未册封、冷宫，权重依次为 8、5、3、2、1、0.5、0。皇后最多一位。分类可改名、调整权重、增加或删除；皇后、未册封和冷宫的特殊规则固定。新增封位位于未册封上方，未册封与冷宫永远在末尾。设置中每行保持名称、权重、保存、删除四列。
- 首页为同尺寸 3:4 卡片的后宫：皇后一位居中，各封位一条横排，窗口逐层加宽，溢出左右滑动并以边缘渐隐提示。后宫仅为展示布局，除皇后外没有人数限制。前三分类按排序使用金、银、铜，后续边框与光效渐暗。
- 点击封位标题与皇冠抽屉分类进入同一个完整分类网格，点击「返回后宫」回到首页。搜索与标签条件保留；当前分类、首页横排位置在数据刷新时保留。每批 24 位，可继续加载全部角色。
- 皇冠打开左侧滑入抽屉，搜索、标签与封位导航集中在其中，手机不保留常驻左栏。筛选时只显示匹配角色及封位，不显示局部空皇后等占位。横排支持触摸／触控板、鼠标拖动、方向按钮和键盘；拖动不误打开档案，减少动态效果时取消淡入和滚动过渡。
- 设置中可选历史／女帝分类。女帝为帝后、贵君、文君、侧君、侍君、未册封、冷宫；切换沿用已有角色册封与权重，手动改过的名字保留。首次升级将旧默认皇贵妃／皇贵君的角色并入贵妃／贵君，旧常在／侍君并入贵人／侍君；旧贵卿改名侍君。手动改名的分类保留，角色记录、原帖及存档偏好不删除；缺少合并目标时移至未册封。
- 翻牌仅由按钮打开。初始界面只显示仿真托盘和五枚牌，规则、盲翻／点名、标签和封位都收进「翻牌设置」。结果在托盘下方独立显示和滚动，不改变托盘位置。桌面与手机均展示五牌；点名不足五位时，其余为不可点击的空牌，不用重复角色填满。
- 托盘使用可验证加载的独立 PNG 图片，不依赖 CSS 背景；托盘前沿、牌子和盘底分层，结合接触阴影与轻微倾角表达牌子放在盘内的效果。手机保留托盘素材原始比例，五枚牌保持可点击。
- 点击或轻触以约 850ms 沿 Y 轴缓起缓停地翻牌，揭晓后轻抬并露出侧边；结果及操作区以 560ms 纯透明度淡入，重新摆牌先淡出旧牌再显现新牌，普通弹窗内容以 280ms 淡入。其他按钮提供约 500ms 的低强度光晕与居中展开的金色下划线，卡框光影以 700ms 缓变。普通控件不位移、不缩放、不做按压浮雕；无音效、无本轮去重，尊重系统减少动态效果设置。
- 完全随机、情有独钟、喜新厌旧、旧情复燃四种规则，始终排除冷宫。
- 档案、开场、关联世界书、同角色多存档集中查看；所有资料、开场和世界书条目的折叠栏默认关闭，使用两线折角标记。移除嵌入世界书重复展示及存档正文预览，资料仍以纯文本显示。
- 点击卡面进入档案，右下角无框播放键继续上次；桌面悬停淡入，手机常驻。可选开场建立新故事、给存档起显示名、置顶、查看原生消息数与最后时间及原生删除。首次打开存档列表时默认置顶上次存档（找不到则用最近一份）。
- 可在插件内编辑原生人设（description），编辑器只保留一个文本框；通过原生接口保存实际改动字段，保存前核对原资料，写入后重新读取验证，失败保留输入。高级标签等仍从原生面板管理。
- 入宫登记包含分类和一个 Discord 原帖。导入支持多个本地文件或原生下载接口支持的 URL。原帖统一从档案外层跳转，缺失时先填写保存；更新／替换面板只提供文件与 URL 导入，不重复原帖入口，也不把 Discord 页面当成下载链接。替换保留角色标识、聊天与登记，不在档案展示翻到／查看计数。
- 管理备份 JSON 导出与恢复；恢复前下载旧配置。角色库快照 ZIP 包含角色 PNG、聊天 JSONL、已关联世界书和管理备份。

## 翻牌规则与时间口径

- **完全随机**：每张非冷宫角色卡权重都是 1。
- **情有独钟**：单卡权重等于其封位权重。默认从皇后的 8 到未册封的 0.5，不保证高位每次出现。
- **喜新厌旧**：单卡权重取封位权重的倒数，与是否没玩过无关。
- **旧情复燃**：只考虑有实际聊天记录的角色。权重为 `log₂(1 + 历史用户消息数)² × (1 + ln(1 + 距上次游玩的天数))`，未玩天数上限 3650；历史投入为主。原生用户消息数作为历史投入，避免将每次重抽的 AI 回复再当作一次投入。封位不参与这项计算。未游玩时长只依据真实互动；原生 date_last_chat 和文件修改时间不参与。旧卡缺日期时先补读候选历史，确认不到则不参与此模式。

没有候选时提示更换规则或筛选，不会悄悄换模式。没有统计数据时，旧情复燃显示错误和重试入口，不冒充完全随机。

入宫优先核对原生持久化 create_date 与已保存的更早导入记录，date_added 仅是可能变化的文件时间。旧卡原始记录丢失／重置时，用最早原生存档建档／消息日期校准，并在档案注明这是历史推定；不能宣称它必然等于首次导入。插件明确观察到的新导入不会被复制来的旧聊天反推。均不可用则显示未知。「入宫 xx 天」按这一日期到今天的本地自然日计数，入宫当天为第 1 天；实际陪伴按原生聊天日期另算，不参与封位权重。

未游玩时长从最近一次真实互动开始计算：实时记录使用设备当时的时刻，历史读取消息／生成时间（包括保留的生成分支）。续写和重抽的新生成更新互动时间，但不加新楼层；编辑元数据、文件修改、切换已有回复、查看或打开存档不刷新时间。日期缺失保持未知，旧记录不覆盖较新的真实互动。

翻到、查看、进入存档、实际聊天分别记录。只打开旧档不会更新实际游玩；实际聊天通过非群聊的原生消息事件记录。历史投入来自原生用户消息数。首页和面板刷新不读取整库聊天正文；仅在打开档案且缺少已记录初见日期时，对该角色逐档补读消息日期，结果缓存且只保存日期。已有日期直接沿用，不重复整档下载。存档页仅读列表及原生消息数，不再提供正文预览。日期缺失／读取失败显示待补全，不冒称尚未初见。

## 备份边界

管理 JSON 不含角色正文或聊天正文。角色库快照 ZIP 是当前角色库的逐项读取快照，不是整个账号的完整备份：不含群聊、外置图片／脚本资源、预设、API 配置和整个酒馆设置。超过 256 MB 停止并提示使用酒馆原生数据备份。生成失败时不提供假装完整的压缩包。

首版仅自动恢复管理 JSON。ZIP 中的角色、聊天、世界书由用户通过酒馆原生入口导入，`index.json` 记录其对应关系；不会自动覆盖恢复真实聊天。正在聊天的同时导出，文件间可能存在时间差，建议空闲时导出。

## 已知限制与验证

本版已通过规则／接口模拟测试、浏览器离线交互和 320／390 像素竖屏检查；当前工作区没有连接真实 SillyTavern，**未完成真实酒馆安装、聊天保存、开场切换、更新替换和世界书跳转验收**。请按 `docs/RUNTIME-CHECKLIST.md` 进行首轮试用。

原生标签编辑和角色创建由原生界面负责。第三方深度改造首页／角色抽屉的美化可能影响挂载，可关闭首页展示或「替代右上角原生角色面板」，从扩展设置中的「打开管理器」进入。世界书预览不会执行 EJS、宏或脚本。角色面板替代已通过模拟宿主 DOM 检查，仍需在真实酒馆确认抽屉、固定／拖动、创建和编辑流程。

## 开发

源码在 `extension/`，设计原稿保留在 `design/`。无框架、无线上 CDN 依赖，压缩库 fflate 已随包附带及保留 MIT 许可证。

```powershell
npm test
npm run check
npm run test:ui
npm run package
npm run preview
```

静态检查／UI 检查／离线预览打包需要开发依赖 `css-tree`、`playwright-core`、`esbuild` 和可用 Chrome；工具可使用工作区现有安装，或执行 `npm install`。Chrome 路径可用 `CHROME_PATH` 指定。浏览器测试使用本地文件响应，不请求外网。
